# Website Chatbot Setup Guide

This project now includes a starter website chatbot (`/api/chat/ask`) plus a floating UI widget.

## 1) How it works
1. Visitor asks a question from the website chatbot widget.
2. Frontend sends message to `POST /api/chat/ask`.
3. Server builds chatbot context from:
   - `settings.chatbot_knowledge` (database, optional),
   - `app/data/chatbot_knowledge.md` (file-based baseline),
   - basic business settings (phone/email/address/GST).
4. If `OPENAI_API_KEY` exists, response is generated by OpenAI Responses API.
5. If no API key (or API failure), server returns a safe fallback answer.

## 2) How to give all information to the bot
Use **both** methods for best control:

### Method A — File based (recommended for version control)
Edit: `app/data/chatbot_knowledge.md`
- Add services, turnaround policy, print specs, FAQ, payment/shipping rules.
- Keep information factual and short.

### Method B — Admin/DB based (runtime updates)
Save long-form business FAQ in setting key: `chatbot_knowledge`.
- Useful when non-technical team wants updates without code deploy.

## 3) "Training" the bot (practical meaning)
For this website bot, "training" means **prompt + context tuning**, not full model fine-tuning.

### Recommended training loop
1. Collect real visitor questions.
2. Add missing answers to knowledge file or DB setting.
3. Add clear policy lines (delivery windows, cancellation rules, etc.).
4. Re-test top 30 FAQs weekly.
5. Add handoff rules for sensitive cases (refunds, complaints, custom quotes).

## 4) Environment variables
Add in `.env`:

- `OPENAI_API_KEY=...`
- `OPENAI_MODEL=gpt-4.1-mini` (optional)

Optional governance vars you can add later:
- max chat turns per session
- rate limits per IP
- allowlist/denylist keywords

## 5) Website embedding
Already added globally via `includes/partials/footer.php` and `assets/js/app.js`.

UI behavior:
- Floating button opens chat panel.
- Sends question to API.
- Renders assistant response.
- Shows "Talk to Human" action for escalation.

## 6) Recommended production upgrades
- Add rate limiting per IP/session to `/api/chat/ask`.
- Add moderation/safety filter for abusive input.
- Store chat transcripts in DB for quality improvements.
- Add language switch (English/Hindi/Gujarati).
- Add analytics: deflection rate, handoff rate, unresolved topics.
